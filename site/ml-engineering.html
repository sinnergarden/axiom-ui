流程与职责

Feature/Label → Model → 原始 Prediction → 组合 Signal → 信号评价 → 策略账户。Data 保存事实；Research 管训练输入、模型、预测与信号评价；Engine 管账户执行和评价；UI 只读展示保存结果。

def case_path(relative):
    value = Path(relative)
    if value.is_absolute():
        raise ValueError("配置位置应相对 AXIOM_M1_ROOT")
    result = (ROOT / value).resolve()
    if not result.is_relative_to(ROOT):
        raise ValueError("配置位置超出验收根目录")
    return result

def read_small_json(path, maximum=16 * 1024**2):
    # 只读配置和小型索引；矩阵及来源闭包交给正式 reader。
    with Path(path).open("rb") as saved:
        raw = saved.read(maximum + 1)
    if len(raw) > maximum:
        raise ValueError("小型配置超过读取预算")
    return json.loads(raw)

@contextmanager
def measure(stage, api_metrics=None):
    # 计时探针只记录调用；业务由下面各单元直接执行。
    before = resource.getrusage(resource.RUSAGE_SELF)
    started = time.perf_counter()
    record = {"stage": stage, "status": "RETURNED"}
    try:
        yield
    except BaseException as error:
        record.update(status="ERROR", error_type=type(error).__name__)
        raise
    finally:
        after = resource.getrusage(resource.RUSAGE_SELF)
        record.update(elapsed_seconds=time.perf_counter() - started,
            rss_process_peak_bytes=int(after.ru_maxrss * (1 if sys.platform == "darwin" else 1024)),
            input_block_ops_delta=after.ru_inblock - before.ru_inblock,
            output_block_ops_delta=after.ru_oublock - before.ru_oublock,
            api_metrics={} if api_metrics is None else api_metrics)
        with timing_path.open("a", encoding="utf-8") as output:
            output.write(json.dumps(record, ensure_ascii=False, allow_nan=False) + "\n")
        print(record)

CaseC：准备一次，保存四折，再运行 Top5

  1. 目的与输入。 固定六列 Feature、实际五交易日 Label、四折日历和时钟，检查成熟训练、原始 OOS 预测、唯一 Runtime 账户及资源成本。完整 Feature 输入须覆盖训练窗；505 交易日 Feature 已验通过，Label 与四折保存件仍待本次贯通验证和交接。
  2. 准备与预期。 下方只调用一次 prepare，生成共享 prepared view 和四折 selectors，Data 保持 cache_bytes=0。首次精确定义为 MISS；已有同定义保存件可 HIT，两种结果均记录实际计数。HIT 的 Data/Core/fit/predict/account 调用应为零。prepare 不重新 build Feature，完成后沿正式实现释放当前 Data 实例缓存。
  3. 要看什么。 检查准备耗时、逻辑 Data 调用、Core 调用、实际读/hash 字节和工作集峰值。物理分区计数尚未由公共 Data API 暴露时，保留正式报告中的空值和原因。这里的 Data 内存缓存与磁盘 prepared HIT 分别解释。

具体日期怎么读。 选本次第一折的一个交易日 D〔待填：oos_trade_sessions 中的实际日期〕，从同一冻结日历取其严格前一交易日 F〔待填：对应预测日期〕；再读取这折的拟合日 T〔待填：fit_session〕。四折产物交接后逐项填入原值；以下 20:30、20:45、21:00 来自当前正式 fold 时钟定义，日期暂留待填。阅读时统一显示上海时间，保留原保存时钟。

  1. Feature 可见。 F〔待填〕这次预测使用的原 Feature 可见时间〔待填：feature_available_at〕、事实选择截止时间〔待填：feature_knowledge_cutoff〕和成员资格，须在本次推理截止时间内有效。输入沿原 Feature 保存件核验，缺失或不可见状态继续保留。
  2. 训练 Label 成熟。 由 owner 从本折实际训练键中选一条日期 g〔待填〕，列出其 Raw Label 起日〔待填：start_session〕、止日〔待填：end_session〕和可用时间〔待填：label_available_at〕。当前 5D 定义为 g 后第一个交易日开盘至第五个交易日收盘的复权收益；训练要求止日不晚于拟合截止日期、Label 可用时间不晚于 fit_cutoff，并通过原成员和 Feature 资格筛选。F 的未来 5D 收益留给独立评价，训练只使用拟合时已经成熟的样本。
  3. Model 可用。 读取 fit_cutoff〔T 待填，20:30 +08:00〕和 simulated_model_available_at〔T 待填，20:45 +08:00〕。它们是本折声明的模拟拟合与发布时钟；本次真实准备、fit、predict 耗时继续从阶段记录读取。
  4. Prediction 发布。 原始预测的 session 为 F〔待填〕，knowledge_cutoff 与 available_at 均取 inference_cutoff_by_session[F]〔F 待填，21:00 +08:00〕，同时保留这次实际使用的 model/fold 和原 Feature 时钟。模型可用时点早于此次发布；更换事后评价 Label 时，这份预测及其生成时参考截面保持固定。
  5. 下一交易日执行。 Runtime 在 D〔待填〕按已验请求读取上述预测，用当日执行行情、成员、规则和费用推进账户。D 由冻结交易日历定位，周末和休市日直接沿日历跨过。订单、成交、ledger 与扣费 NAV 从本次保存账户读取；独立 Label 统计另从信号评价读取。

三个用例的可执行范围。 同数据换 model：准备复用、固定参数训练和同配置 HIT 已有入口，saved-fold 两字段候选已有 helper unit 结果，真实保存闭环与本页接入仍待完成。同一评价 Label 比不同 prediction：OOS 冻结、显式 Raw Label、共同成熟样本和自然覆盖已有入口，补齐两组真实预测与评价引用即可调用；固定加权组合的保存执行/准入、按年汇总和分组收益仍待实现。同 signal 换策略：正式 Runtime 可消费相同已准入预测与不同已支持策略请求；本页当前接 50 万元 Top5，其余策略请求和预算由 Engine owner 另行交接，超出现有 policy 的能力单列待实现。六个业务单元仍未执行；505 交易日 Feature 已验，待 Label 与四折保存件交接后逐项验收。
